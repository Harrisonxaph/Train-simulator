# V1.1 review and verification

Scope: incremental empty startup, independent crossings and two-cell left/right switches. The existing Canvas renderer, React controls, train artwork, audio, camera and local persistence architecture are retained. No dependencies were added.

A fresh read-only reviewer inspected startup, graph separation, geometry, active routing, switch occupancy, save migration, history, pointer offsets and controls. No critical or important gameplay findings were established. The reviewer identified stale V1 documentation; README and AGENTS now describe V1.1.

Visual verification then reproduced a zero-size Canvas failure during a temporary hidden-container resize. A failing Playwright regression confirmed `drawImage` received a zero-size cached canvas. The resize observer now retains the previous drawable buffer and camera until the container has usable dimensions. The regression passes on desktop and phone Chromium.

Automated coverage includes all four crossing traversal directions, both switch handednesses and alignments, aligned reverse entry, inactive-route stopping, continuous branch tangents, independent loops sharing crossings, live nose/tail occupancy locks, route changes ahead without moving the train, footprint bounds/overlap, history, V1 migration and V2 path/alignment validation. Browser scenarios use actual construction controls and cover empty startup, legacy saves, all five cards, both crossing axes, both switch branches, occupancy-disabled controls, switch history/refresh, second-cell dragging, crossing placement-path persistence and actual touch swiping/tap placement.

Limitations: physical iPhone/iPad Safari has not been tested; phone coverage uses Chromium touch emulation. Unmarked legacy demo-shaped saves remain intact because they cannot safely be distinguished from user creations. Only explicitly marked auto-demo records receive special empty-start handling. One active train remains supported. Multi-train traffic management, stations and unrelated original roadmap items remain outside this update. No production merge or deployment is performed by this implementation.

See `v1.1-progress.md` for exact final command results.
